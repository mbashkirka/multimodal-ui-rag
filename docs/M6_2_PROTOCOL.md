# M6.2 Protocol — Categorical Evidence Selection

## Frozen retrieval

The M5 production retriever stays frozen:

`SigLIP2 Base NaFlex p256 → FlatIP exact Top-20 → p512 50/50 RRF rerank → Top-4 evidence`.

## Selector

The four Top-4 evidence screenshots are rendered into one 2×2 contact sheet. Each cell has a visible `E1`–`E4` banner. The complete sheet is kept under the same Qwen2.5-VL visual budget used in M6.1.

The VLM receives the user description plus this single contact sheet and is allowed to emit only a categorical choice semantically:

`E1 | E2 | E3 | E4 | NONE`.

The parser tolerates superficial punctuation but rejects ambiguous outputs containing multiple choices. Citations are not generated by the model; the application maps the selected label back to the corresponding evidence object.

## Interactive answer

For a non-`NONE` selection, the same already-loaded MLX VLM is called a second time with **only the selected screenshot**. It produces concise grounded prose. The application attaches the selected evidence ID deterministically. If the single-image answer stage returns `INSUFFICIENT_EVIDENCE`, the application abstains.

## Evaluation

M6.2 selector development uses a deterministic balanced sample from Screen2Words **dev**:

- 20 cases where the exact target is in Top-4;
- 20 cases where the exact target is absent from Top-4.

Primary selector metric: exact target selection accuracy conditioned on retrieval-hit cases.

Supporting metrics:

- selector parse-valid rate;
- end-to-end exact selection rate;
- retrieval-rank-1 baseline accuracy on hit cases;
- selector gain/loss versus always selecting E1;
- abstention rate on miss cases (diagnostic only);
- selector latency.

The M6.1 test diagnostic is not reused for M6.2 prompt tuning.
